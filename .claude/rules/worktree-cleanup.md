# worktree は PR 作成後に削除する（worktree cleanup）

## 原則

**issue / 作業単位ごとに作った git worktree は、その作業の PR を作成した時点で役目を終える。PR を作ったら worktree を削除する。**

worktree 自体は `.git` を共有するため軽いが、**各ツリーに `node_modules` やビルド成果物（iOS/Android のビルド、Pods 等）が個別に生成される**ため、1つあたり数百 MB〜1GB に膨らむ。放置すると数十 GB 単位でディスクを食う。

## やること

1. PR を作成し、push が済んだことを確認する（**worktree を消してもブランチと PR は残る**）
2. worktree を削除する
   ```bash
   git worktree remove <path>       # 未コミットがあると失敗する（安全弁）
   git worktree prune               # 手動で消えたツリーの参照を掃除
   ```
3. `git worktree remove` が失敗したら、**強制削除する前に中身を確認する**
   - 生成物・ログのみ（`node_modules`, ビルドログ等）→ `--force` で削除してよい
   - **ソースの未コミット変更がある** → 削除せず、コミットするか捨てるかをユーザーに確認する
4. **ブランチは削除しない**（worktree の削除とブランチの削除は別。ブランチ削除は明示的な指示があるときだけ）

## 判断基準

- **「この worktree でやることはもう残っていないか？」** → PR を作ったなら基本は残っていない
- **「レビュー指摘の対応が続くか？」** → 続くなら残す。指摘対応も PR にマージされ切ったら削除する
- **「消して困るものが中にあるか？」** → `git status` が生成物・ログだけなら困らない

## 禁止

- PR 作成後の worktree を無期限に放置する
- 中身を確認せずに `--force` で削除する
- worktree 削除のついでにブランチを消す（指示がない限り）

## 補足

削除の取りこぼしは定期的に棚卸しする。`git worktree list` で一覧し、ベースブランチにマージ済みのブランチを指す worktree は削除候補。
